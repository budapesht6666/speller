# План: игра для изучения слов через произношение

## Контекст

Строим PWA-игру: сверху падают предметы, игрок вслух называет их на изучаемом
языке, успел — сбил, не успел — раунд окончен. Язык на старте `en-US`,
конечная цель — «приехал в новую страну, учишь местные слова».

Исследовательская фаза закончена, её результаты в `PROBE-RESULTS.md`. Главное:
**`SpeechRecognition` работает в standalone на iOS 18.7 / Safari 26.6**, поэтому
берём уровень A (Web Speech API), Azure не нужен. Но диагностика заодно показала,
что наивный матчер не заработает, и это определяет архитектуру ядра.

Теперь строим само приложение. Требования, добавленные к исходным: **выглядеть
премиально**, **никаких эмодзи**, **все ассеты бесплатные**, **завести
дизайн-систему**. Визуальные референсы — `references/play_screen.jpg` и
`references/finish_screen.jpg`.

Репозиторий: **https://github.com/budapesht6666/speller** (сейчас в нём только
README). Текущий рабочий каталог `lang-game_research` под гитом не находится, его
содержимое переезжает в репозиторий первым коммитом.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Визуальный язык | Мягкий 3D по экрану проигрыша: градиентное небо, объёмные предметы, стеклянные пилюли, мягкие тени |
| Ассеты | Streamline free, CC BY 4.0, со ссылкой-атрибуцией |
| Порядок работ | Сначала дизайн-система и статичные экраны, потом игровой цикл |
| Анимация | GSAP (полностью бесплатен со всеми плагинами с апреля 2025) |

## Ограничения ядра, вытекающие из диагностики

Это не пожелания, а измеренные факты — код обязан их учитывать:

- **Решение принимаем по `interim`** — он даёт реакцию за 0.2–0.4 с после
  произнесённого слова. `FINAL` не используем: он приходит через ~2 с после того,
  как игрок замолчал, то есть слова, названные подряд, им не отследить вовсе.
- **В `interim` ровно одна альтернатива и `confidence = 0.00`.** Отсекать по
  уверенности не на чем, `maxAlternatives` помогает только на финале.
- **Короткие слова искажаются систематически:** `ball` → «Bowl», `tree` → «free».
  Фонетическое сравнение обязательно, точное совпадение строк не работает.
- **`phrases` на Safari нет** — подсказать движку слова с экрана нельзя.
- **Микрофон захватывается один раз за сессию и не отпускается.** После
  освобождения следующий захват на Safari приходит мёртвым без ошибки.
- **Сессия живёт ≥58 с без обрыва**, авторестарт по `onend` нужен только как страховка.
- **Распознавание серверное** — офлайн игра не работает, это надо честно показать.

## Стек

Vite + TypeScript, без фреймворка. GSAP для движения. Vitest для тестов матчера.
Astro из скилла `promo-site` не берём — он под статические лендинги, а тут
одностраничное приложение. Но `tokens.css` и идею живого стенда `/design-system`
оттуда заимствуем: структура и обоснования в
`shared-claude-skills/skills/promo-site/references/design-system.md`.

Зависимости: `gsap`, `double-metaphone` (MIT, ESM, типизирован, `doubleMetaphone(s)`
возвращает два кода), `@fontsource-variable/nunito`. Левенштейн пишем сами —
это десять строк, пакет ради него не нужен.

Падение фигурок считаем руками в едином тике `gsap.ticker`, а не твинами: нужны
пауза, переменная скорость и попадание по линии. GSAP отвечает за дискретные
события интерфейса — переходы экранов, вспышка попадания, скачок счётчика,
пульсация пилюли «Слушаю». Один тикер на всё приложение, чтобы часы не разъезжались.

## Дизайн-система

Файл `src/styles/tokens.css` — единственный источник значений, ни одного сырого
цвета или кегля в компонентах. Стенд `design-system.html` собирается из тех же
токенов, поэтому разъехаться они не могут.

- **Палитра.** Акцент — оранжевый с референса (кнопка, счётчик, заголовок «Сбит!»).
  Игровой экран: вертикальный градиент неба. Экран проигрыша: белая бумага,
  подложки карточек, текст прозрачностями от `--c-ink`, а не готовыми серыми.
- **Гарнитура.** Nunito (OFL) — округлая, совпадает с характером референса.
  Четыре начертания. Числа статистики — табличные цифры.
- **Шаг 4 px**, шкала кеглей, радиусы, слои — по структуре из `promo-site`.
- **Одна кривая движения** на всё приложение, продублированная массивом для GSAP.
- **Тема одна, светлая.** Вторая удваивает каждый токен и не переживает градиент
  неба; заводить осознанно, если понадобится.
- `prefers-reduced-motion` уважаем: падение остаётся (это суть игры), украшения гасим.

## Ассеты и словарь

Источник: `https://github.com/webalys-hq/streamline-vectors`, наборы
`kameleon/colors` и `plump/gradient` — цветные объёмные SVG, разложенные по темам
(еда, путешествия, природа, спорт, покупки, здоровье, дом). Лицензия CC BY 4.0:
коммерческое использование и переделка разрешены, требуется ссылка на
streamlinehq.com.

**Важное ограничение, влияющее на порядок работ:** бесплатные наборы — витрина,
10–22 иконки на категорию, около 250–300 штук всего. Поэтому **словарь
подбирается под наличие иконок, а не наоборот**. На стартовые 60–80 слов хватает.

Порядок:
1. `scripts/fetch-assets.mjs` — sparse checkout нужных подпапок во временный
   каталог, отбор выбранных файлов в `public/assets/objects/`, генерация
   `src/data/asset-manifest.json`. Скрипт идемпотентен и коммитит результат:
   в рантайме сеть к GitHub не нужна.
2. `src/data/concepts.ts` — понятия, а не слова:
   `{ id, asset, category, labels: { 'en-US': { word, article? } } }`.
   Смена языка обучения = добавление ключа в `labels`, картинка и id общие.
   Это и есть заложенная в задачу возможность сменить страну.
3. `ASSETS.md` — перечень использованных файлов и текст атрибуции.
   Ссылка на Streamline в интерфейсе — на экране «О приложении».

`core/` не знает про DOM, `ui/` не знает про распознавание. Матчер поэтому
тестируется без микрофона и браузера — а он и есть самая рискованная часть.

## Матчер

Вход: строка `interim` и список слов, которые сейчас на экране. Выход: попадание
или ничего. Порядок проверок для каждого кандидата:

1. нормализация — нижний регистр, снятие пунктуации, разбор на слова;
2. точное совпадение;
3. совпадение кодов Double Metaphone (оба кода против обоих);
4. Левенштейн ≤ 1 для слов до 5 букв, ≤ 2 для длинных.

Порог и правила — в конфиге, не в коде. Тесты пишутся на реальных промахах из
журналов: `Bowl`/`Bull`/`Boil`/`Both` → `ball`, `free` → `tree`. Плюс проверка
на ложные срабатывания: русская речь и посторонние английские слова не должны
засчитываться.

Хвост `interim` растёт, а не переписывается, поэтому сравниваем только прирост
с прошлого события, иначе одно слово засчитается многократно.

Бюджет реакции — 0.2–0.4 с от произнесённого слова до попадания. Скорость падения
подбирается так, чтобы у фигурки оставался запас до нижней линии после этой
задержки, иначе правильно названное слово будет иногда не засчитываться.

## Этапы

**M1 — дизайн-система и статичные экраны.** Токены, стенд `/design-system`,
примитивы, ассеты скачаны и отобраны, оба экрана свёрстаны статикой с реальными
картинками и реальным шрифтом, манифест и standalone-метатеги на месте.
Точка утверждения: смотрим на айфоне с иконки, утверждаем вид.

**M2 — игровой цикл.** `recognizer`, `matcher` с тестами, `game`, спавн и падение
в тике, попадание, конец раунда, экран проигрыша с озвучкой подведшего слова.
Точка утверждения: играбельно на телефоне.

**M3 — отделка.** Движение по GSAP: вспышка попадания, скачок счётчика, переход
между экранами, пульсация «Слушаю». Прогрессия сложности, XP и звёзды, экран
«О приложении» с атрибуцией, честное сообщение при пропаже сети.

## Проверка

Локально: `npm run dev -- --host`, стенд `/design-system.html` — ни одного пустого
образца, иначе токен переименовали. `npm test` — матчер на журнальных промахах.

На устройстве, по ходу работы: `cloudflared tunnel --url` на дев-сервер, как в
диагностике. Бинарник уже лежит в скретчпаде сессии.

Для точек утверждения (M1 и M2) лучше **GitHub Pages** из репозитория: адрес
постоянный, поэтому иконка на домашнем экране переживает перезапуск и к тесту
можно возвращаться на следующий день, а туннельная ссылка умирает вместе с
сессией. Публикация делает страницу общедоступной — включаем по отдельному
подтверждению, не молча.

Проверяем именно из иконки: `navigator.standalone === true`, распознавание
отвечает, микрофон берётся один раз за сессию.

Контроль расползания системы:
```powershell
rg "#[0-9a-fA-F]{3,8}\b" src/ui src/styles/base.css   # цвета мимо токенов
rg "font-size:\s*\d" src/ui                            # кегли мимо шкалы
```

## Вне объёма

Смена языка в интерфейсе (архитектура готова, экран настроек — потом), аккаунты и
синхронизация, офлайн-режим (распознавание серверное), оценка качества
произношения через Azure (уровень B — только если понадобится «покажи, где
ошибся»), расширение словаря за пределы бесплатного набора Streamline.
