# Проект: браузерная игра для изучения слов через произношение

## Что строим

PWA-игра: сверху вниз падают фигурки (эмодзи-объекты), микрофон постоянно слушает.
Игрок должен вслух назвать падающую фигурку на изучаемом языке. Успел и произнёс
правильно — фигурка сбита, начисляется XP. Пропустил — раунд закончен, показывается
слово, которое подвело, с озвучкой.

Референс механики — скриншоты из аналогичной игры (пиксельные облака, счётчик звёзд,
индикатор «Слушаю…» внизу, экран проигрыша со статистикой: время / очки / слова).

- Язык обучения на старте: **английский** (en-US), захардкожен для тестирования.
  Архитектура должна допускать смену языка — конечная цель: приехал в новую страну,
  учишь местные слова.
- Установка на домашний экран обязательна.
- Стек по умолчанию: TypeScript. Фронтенд без тяжёлых фреймворков, игровой цикл
  на canvas или DOM — решить на месте.

## Ключевое техническое решение: как проверять произношение

Это не задача «распознать речь», а задача **закрытого словаря**: на экране в любой
момент 1–5 известных слов, надо понять, названо ли одно из них.

### Уровень A — MVP, бесплатно

Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`):

- `lang = 'en-US'` — сам по себе работает фильтром языка: скажешь слово по-русски,
  движок вернёт мусор
- `maxAlternatives = 5` — сверять надо все варианты, не только первый
- `continuous = true`, `interimResults = true` — проверять хвост промежуточных
  результатов против активных падающих слов, не дожидаясь финального
- матчинг: нормализация → точное совпадение → фонетический код (Double Metaphone) →
  Левенштейн ≤ 1 для коротких слов
- в Chrome распознавание **серверное**, аудио уходит в Google, офлайн не работает

### Уровень B — реальная оценка произношения

Azure Speech, **Pronunciation Assessment** (`microsoft-cognitiveservices-speech-sdk`):

- на вход `referenceText: "ball"`, на выходе AccuracyScore / FluencyScore /
  CompletenessScore / PronScore, оценки по фонемам и `ErrorType: Mispronunciation`
- работает в браузере через `getUserMedia` + WebSocket напрямую в Azure, то есть
  **обходит проблему iOS** (см. ниже) и даёт приемлемую задержку для аркады
- ключ Azure никогда не в бандле — короткоживущий токен со своего бэкенда
- известная особенность: при ошибке в одной фонеме проседают оценки всех фонем слова.
  Для вердикта «зачёт/незачёт» годится, для «покажи, где именно ошибся» — нет
- порог засчитывания вынести в конфиг, старт с PronScore ≥ 60, калибровать на людях

### Чего не делать

Whisper (transformers.js или серверный) для этой задачи не подходит: он нормализует
кривое произношение в правильное слово и додумывает по контексту. Даёт ложные зачёты
именно там, где вся суть игры.

## Главный риск: iOS в режиме standalone

Safari на iOS **не даёт использовать Speech Recognition API, когда сайт запущен как
приложение с домашнего экрана**. В обычной вкладке Safari работает, из иконки — нет.
Баг многолетний. Это ломает основное требование проекта.

Также исторически были проблемы с `getUserMedia` в standalone-режиме на iOS
(WebKit bug 185448) и жалобы, что `MediaRecorder` в PWA срабатывает только при первом
запуске приложения.

**Поэтому проверка на живом айфоне идёт раньше любой разработки.**

В репозитории лежит `mic-probe.html` — самодостаточная диагностическая страница.
Проверяет: режим запуска, доступность API, распознавание с вариантами и confidence,
`getUserMedia` + `MediaRecorder`, on-device движок Chromium. Есть кнопка копирования
журнала. Требует HTTPS.

Порядок: открыть в Safari → убедиться, что распознавание работает → добавить на
домашний экран → открыть из иконки → повторить.

Если из иконки прилетает `not-allowed` / `service-not-allowed` — путь через Web Speech
API на iOS закрыт, и весь звук идёт единым потоком через `getUserMedia` + Azure SDK,
без ветвлений по платформам. Это, скорее всего, и станет итоговой архитектурой.

## Побочные факты, которые пригодятся

- Chromium умеет локальное распознавание: `processLocally = true` плюс
  `SpeechRecognition.available()` / `install()` для языкового пакета. Бесплатно,
  приватно, офлайн — но только Chrome/Android.
- В спецификации есть contextual biasing через `phrases` — можно подсказывать движку
  слова, которые сейчас на экране. Ровно наш случай, стоит проверить поддержку.
- Safari обрывает `continuous`-сессию непредсказуемо, нужен авторестарт по `onend`.
- Chrome сам завершает сессию после паузы в речи — авторестарт нужен и там.
- Доступ к микрофону запрашивается только из пользовательского жеста, страница
  обязана быть на HTTPS (или localhost).
- На iOS «Добавить на экран Домой» даёт WebClip, а не полноценный PWA. Standalone
  включается метатегом `apple-mobile-web-app-capable`, манифест по-другому
  интерпретируется, чем в Android Chrome.

## Текущий статус

Диагностика на живом iPhone (iOS 18.7 / Safari 26.6) проведена, оба прогона —
и во вкладке, и с иконки домашнего экрана. Полные журналы и разбор в
`PROBE-RESULTS.md`, протокол проверки в `PROBE-CHECKLIST.md`.

**Главный риск снят: `SpeechRecognition` в standalone работает.** Описанный выше
многолетний баг iOS на этой версии не воспроизводится. Выбран **уровень A** —
Web Speech API. Azure переходит в разряд опционального: он понадобится, только
если захочется оценивать качество произношения, а не факт угадывания слова.

Что это меняет в плане матчера по сравнению с исходными предположениями:

- решение принимаем по `interim`, `FINAL` опаздывает примерно на 2 секунды;
- в `interim` приходит ровно одна альтернатива и confidence всегда `0.00`,
  так что `maxAlternatives = 5` помогает только на финале;
- фонетическое сравнение обязательно: `ball` распознаётся как «Bowl»,
  `tree` — как «free», причём в финале правильный вариант оказался пятым
  при одинаковом confidence у всех пяти;
- `phrases` на Safari не поддерживается — biasing отпадает;
- микрофон захватывать один раз за сессию и не отпускать: после освобождения
  следующий захват на Safari приходит мёртвым без ошибки.

Непрерывная сессия в standalone прожила 57.8 с и оборвалась только вручную,
из них 53 секунды — полная тишина. Safari не рубит `continuous` по паузе в речи,
так что бесшовный авторестарт с перекрытием не нужен, хватит восстановления
по `onend` как страховки. `MediaRecorder` в standalone тоже исправен — нули
в первом замере вызвало освобождение микрофона, а не режим запуска.

Диагностика закончена. Следующий шаг — прототип игрового цикла на уровне A.
