# Результаты диагностики

## Прогон 1 — вкладка Safari, iPhone

- iOS 18.7, Safari 26.6 (`Version/26.6 Mobile/15E148`)
- `mode=browser`, `navigator.standalone=false`, `secureContext=true`

### Доступность API

| Что | Результат |
|---|---|
| `SpeechRecognition` (webkit) | есть, **работает** |
| `getUserMedia` | работает, `label="Микрофон iPhone"`, 48 кГц, пиковый RMS 0.146 |
| `MediaRecorder` | создаётся, но см. раздел про форматы |
| contextual biasing (`phrases`) | **нет** |
| `SpeechGrammarList` | не используется |

### Тайминги распознавания

| Событие | Задержка |
|---|---|
| `SR.start()` → `onstart` | 1.05 с в первой сессии, 0.01 с во второй (первый раз — запрос разрешения) |
| `onstart` → `onaudiostart` | мгновенно |
| начало речи → первый `interim` | ~0 (приходят одновременно) |
| слово → его появление в `interim` | 200–400 мс |
| конец речи → `FINAL` | ~1.9 с |

**Вывод для игрового цикла:** матчить только по `interim`. `FINAL` опаздывает почти
на две секунды — за это время фигурка успеет упасть.

### Три ограничения, определяющие архитектуру матчера

1. **Альтернативы есть только в `FINAL`.** Все `interim` приходят строго с `alts=1`.
   В реальном времени доступен ровно один вариант распознавания, запасных нет.
2. **Confidence в `interim` всегда `0.00`.** Число появляется только в `FINAL`
   (0.89 и 0.79). Строить порог засчитывания на confidence нельзя.
3. **Короткие слова распознаются неверно.** Сказано `ball apple tree house water`,
   получено `Bowl apple free house water`. То есть:
   - `ball` → «Bow» / «Bowl» / «Both» / «Boil»
   - `tree` → «free»

   В `FINAL` правильный `Ball` оказался лишь в **пятой** альтернативе, причём
   у всех пяти был **одинаковый** confidence 0.79 — ранжировать по нему бесполезно.

**Вывод:** точное сравнение строк не годится в принципе. Фонетический матчинг
(Double Metaphone) — не улучшение, а обязательное условие. `Bowl`/`ball` и
`free`/`tree` обязаны считаться попаданием.

### Форматы MediaRecorder — исправленный вывод

Первое измерение показало 5 байт (пустой контейнер) для `audio/webm;codecs=opus`,
дважды подряд. Повторный прогон с перебором всех форматов дал совсем другое:

| Запрошено | Отдано | Размер |
|---|---|---|
| `audio/mp4` | `audio/mp4; codecs=mp4a.40.2` | 49 252 байт |
| `audio/mp4;codecs=mp4a.40.2` | `audio/mp4; codecs=mp4a.40.2` | 47 736 байт |
| `audio/webm;codecs=opus` | `audio/webm; codecs=opus` | 54 239 байт |
| `audio/webm` | `audio/webm; codecs=opus` | 53 240 байт |
| (дефолт) | `audio/mp4; codecs=mp4a.40.2` | 49 035 байт |

Пишут **все**, включая webm. `isTypeSupported` не врёт.

**Настоящая причина пустой записи.** Разница между прогонами ровно одна: в первом
запись стартовала *после* того, как блок 4 остановил треки и закрыл `AudioContext`;
во втором поток блока 4 оставался живым. То есть после освобождения микрофона
следующий захват на Safari приходит мёртвым — `getUserMedia` отдаёт `state=live`,
а данных в нём нет.

**Вывод для игры:** захватывать микрофон один раз при старте и держать поток всё
время сессии. Не брать и не отпускать его на каждый раунд — второй захват может
оказаться пустым без единой ошибки.

## Прогон 2 — standalone с иконки домашнего экрана

`mode=STANDALONE`, `navigator.standalone=true`, `display-mode=standalone`,
та же iOS 18.7 / Safari 26.6.

### Главный результат: баг iOS не воспроизводится

`SpeechRecognition` в standalone **работает**. Полный цикл событий:

```
[29.85] SR onstart (сессия #1)
[29.85] SR onaudiostart
[35.37] SR onspeechstart
[35.37] interim #0 alts=1: "I"(0.00)
   ... 7 промежуточных результатов ...
[38.27] FINAL #0 alts=2: "12345"(0.88)  "I 12345"(0.88)
```

Ни `not-allowed`, ни `service-not-allowed`. `getUserMedia` тоже работает:
`label="Микрофон iPhone"`, пиковый RMS 0.0963.

**Следствие: уровень A (Web Speech API) жизнеспособен.** Требование «установка
на домашний экран» больше не конфликтует с распознаванием. Azure из обязательного
превращается в опциональный — он нужен только если понадобится настоящая оценка
произношения, а не факт угадывания слова.

Отдельно проверено побочно: `SpeechRecognition` и `getUserMedia` работали
**одновременно** (SR стартовал на 29.08, захват — на 32.70), и распознавание
при этом продолжало выдавать результаты. Для уровня B это важно: можно и слушать
движком, и параллельно снимать сырой звук.

### MediaRecorder: причина найдена

Первый замер в standalone дал нули во всех форматах. Контрольный прогон, где
запись была **первым действием** после запуска (блоки 3 и 4 не трогались):

| Запрошено | Отдано | Размер |
|---|---|---|
| `audio/mp4` | `audio/mp4; codecs=mp4a.40.2` | 48 338 байт |
| `audio/mp4;codecs=mp4a.40.2` | `audio/mp4; codecs=mp4a.40.2` | 48 690 байт |
| `audio/webm;codecs=opus` | `audio/webm; codecs=opus` | 54 056 байт |
| `audio/webm` | `audio/webm; codecs=opus` | 51 991 байт |
| (дефолт) | `audio/mp4; codecs=mp4a.40.2` | 46 791 байт |

**`MediaRecorder` в standalone полностью исправен.** Виноват не режим запуска,
а освобождение микрофона: после `track.stop()` и `AudioContext.close()` следующий
`getUserMedia` отдаёт поток с `state=live`, в котором нет данных. Ошибки при этом
не возникает нигде — ни в `getUserMedia`, ни в `MediaRecorder`.

Правило для игры: **захватить микрофон один раз при старте и не отпускать до
конца сессии.**

### Длительность непрерывной сессии

Замерено в standalone: сессия прожила **57.8 секунды** и завершилась только
ручным «Стоп». Речь прозвучала на 42-й секунде, после неё 53 секунды полной
тишины — и ни одного `onend`.

Safari **не обрывает** `continuous`-сессию по паузе в речи, во всяком случае
в пределах минуты. Значит бесшовный авторестарт с перекрытием сессий не нужен;
достаточно обычного восстановления по `onend` как страховки.

Потолок не измерен — известно лишь, что он больше минуты.

Побочно: на прогретом движке `SR.start()` → `onstart` занимает 0.00 с.
Замеченные ранее 1–2.6 с — разовая плата за первый запуск и запрос разрешения.

## Итог: какой уровень выбираем

**Уровень A, Web Speech API.** Главное препятствие устранено. Ограничения, с которыми
придётся жить и которые определяют конструкцию матчера:

- решение принимаем по `interim`, а не по `FINAL` (тот опаздывает на ~2 с);
- в `interim` ровно одна альтернатива и никакого confidence;
- короткие слова систематически искажаются, поэтому фонетическое сравнение
  обязательно, а не «на будущее»;
- contextual biasing (`phrases`) на Safari недоступен — подсказать движку слова
  с экрана нельзя;
- микрофон захватывать один раз за сессию и не отпускать;
- распознавание серверное: без интернета игра работать не будет.
